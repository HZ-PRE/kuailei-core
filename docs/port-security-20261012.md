# 本地端口加固（2026-10-12）

本次只调整客户端 App 和内核的本地监听。8084、后端 API 配置、Java 进程和防火墙未修改。

## 默认行为

| 默认端口 | 用途 | 调整后的行为 |
| --- | --- | --- |
| 12334 | HTTP / SOCKS 混合代理 | App 桌面端默认开启，手机端默认关闭；仅回环监听，设置中的开关实际控制内核监听 |
| 12335 | Linux TProxy | 默认关闭，明确开启且满足平台和权限条件时才监听 |
| 12336 | Linux / macOS redirect | 默认关闭，明确开启且满足平台条件时才监听 |
| 12337 | 本地 direct / DNS 入站 | 默认关闭，明确开启后仅回环监听 |
| 16756 | Clash 管理 API | 保持回环监听；自动生成 32 字符密码学随机令牌，生成失败返回错误；显式令牌不足 16 字节时报错 |
| 17078 / 17079 | App 与内核 RPC | 保持已有回环监听、TLS 和令牌认证机制 |
| 18020 | 旧版 tunnel RPC | 禁用旧无鉴权服务及其调用入口；保留操作系统层面的 stop / uninstall 清理入口 |
| 可配置调试端口 | debug HTTP / pprof | debug HTTP 仅接受数字形式回环地址；libbox pprof 固定监听 127.0.0.1 |

## 兼容性与边界

- 已明确保存的端口开关继续生效，不覆盖用户原有选择。升级前保存为开启的可选端口，需要在设置中关闭，并重新连接后生效。
- 内核现在识别 `enable-mixed-port`、`enable-tproxy-port`、`enable-redirect-port`、`enable-direct-port`。此前 App 已序列化这些字段，但内核没有读取。
- 内核调用方省略开关时，混合代理随 TUN 状态选择默认值（TUN 开启时默认关闭）；其他三个可选入站默认关闭。App 会显式传入其偏好，桌面端开启 TUN 不会自动覆盖混合代理开关。
- 系统代理模式要求开启混合代理，否则返回清晰错误。App 自带 TUN 不依赖旧版 tunnel 服务。
- 为兼容系统代理，12334 仍为无认证本地代理，本机其他进程仍可访问。仅回环监听限制网络暴露，不提供本机进程隔离。
- 配置生成器拒绝旧的 LAN 共享选项。独立运行模式保留生成器创建的 Clash 地址和令牌，避免覆盖为空令牌配置。
- 未使用的旧配置 gRPC 启动函数也已禁用，避免开启无认证监听。
- 高级调用方通过 `EnableFullConfig` 导入的自定义入站不属于上述生成器监听约束；当前 App 未启用此模式。
- 可选调试服务限制为本机访问，但未新增令牌认证。
